## 页面与交互设计

### A. 主窗口（参考图左上）

- 采用简洁的浅色、细微蓝色强调、低噪声层次；避免原先密集的渐变、重边框、装饰性阴影。
- 顶部歌曲信息区：封面（存在则使用现有 `cover_art_ready` 数据，没有封面时用合理占位）、标题、歌手以及其他可得元数据；不可为了显示示例的年份、专辑和收藏图标而增加数据库字段或假按钮。长标题省略或滚动且提供完整提示。
- 进度条、当前时间/总时间可见、清晰，未知时长不显示虚假总时长；现有点击/拖动 seek、暂停 seek、恢复位置行为不变。
- 控制行让 **播放/暂停成为唯一突出主按钮**；上一首/下一首、播放模式次之；音量放同一行最右端，采用低对比度小图标＋短滑杆。若空间不足，优先保住播放主控，音量可退化成点击弹出的轻量调节，不得产生重叠。音量鼠标、滚轮、键盘和音量持久化必须继续有效。
- 参考图显示随机和循环分开的图标；现有项目具有 ListLoop、SingleLoop、Shuffle、Sequential 四个模式。可以合理调整展示与操作，但**必须保留四种模式及原语义**，模式控件的可用状态、tooltip、accessibleName 与真实模式一致，不放无效按钮。
- 下方导航为“播放列表 / 歌词”。播放列表默认显示；歌词页复用现有 `lyrics_widget`，歌词不存在时有自然空态。切换视图不得打断音乐。**没有“频谱”标签或频谱页面**。
- 歌单栏的“添加 / 管理”入口清楚；新增/重命名/删除歌单、添加/移除歌曲、列表树展开、右键菜单及 Ctrl+M 仍可操作。歌曲行显示可获得的标题/歌手/时长；元数据缺失时自然退化，不要伪造数据。当前播放行要明确但不刺眼。行末更多操作如果无法真正接入既有命令则不要放占位按钮。
- 窗口最小化、关闭/系统托盘、无托盘退出、窗口拖动和尺寸变化必须维持既有逻辑。不要加入没有真实 maximize 行为的假控件。

### B. 歌单管理（参考图左下）

- 双栏“源歌单 / 目标歌单”，中央复制/移动/移除命令区；清晰的复选框、选中状态和歌曲数量。可以复用现有管理页布局、模型与事务保存路径。
- 维持先暂存、应用时原子提交；“取消”放弃未保存更改；无更改的“返回播放”应当直接返回，不必启动写事务。数据库保存失败仍留在管理页。
- 不可删除本地音乐文件；移动/复制/删除目标语义与现有实现一致。避免源/目标相同时触发无效操作。全选/取消全选不要为每个 item 触发完整 O(N) 列表重算，必要时用 `QSignalBlocker` 批量更新后一次刷新。
- 搜索框在确有必要时仅作 UI 过滤，不改数据库结构。窗口缩窄时命令栏、复选框、歌单名称均不能叠压。

### C. 移除频谱功能：不只是隐藏

- 当前 `player_window.cpp` 创建 `spectrum_widget`，`playback_controller.cpp` 的 `set_spectrum_widget`、`on_player_ready_for_spectrum`、`on_spectrum_ready_for_decoding`、`on_packet_for_spectrum`、`start_spectrum_or_decoding` 参与播放器就绪、启动解码、跳转后恢复。请先画出实际启动/seek/停止状态路径，再修改。
- 删除无用频谱 Widget、频谱绘制、FFT/processor 线程、包回调、源文件/CMake 引用及相关资源；若发现某个组件仍有独立功能用途，应说明并保留最小必要部分。不要更改不相关解码、播放队列或音频后端。
- 将就绪→恢复解码与 seek→恢复解码收口到清晰单一路径，仍严格校验 session_id 与 is_seeking；保留暂停、重复 seek、停止与旧回调隔离逻辑。杜绝卡住、重复恢复、已结束会话误触发。
- 检查删频谱后产生的无用 FFmpeg/FFT 依赖、声明、资源与线程是否能移除，但只处理真正不再被使用的部分。

## 决策优先级

1. 真实功能、播放稳定性与已有数据完整性
2. 用户确认的视觉层级：醒目播放、弱化音量、无频谱
3. 紧凑桌面窗口可用性和清晰歌单操作
4. 简化代码与资源占用
5. 视觉细节还原

如果设计参考中的“收藏”“更多”“年份”“搜索”等视觉元素在现有功能里没有可用的数据或操作，优先**省略而不是制造无效入口或引入本轮无关的数据库/功能扩张**。需在最终报告说明取舍。
